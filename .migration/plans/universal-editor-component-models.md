## Goal
Add Universal Editor (xwalk) component models for every content block in the repo. The project stays a **Document Authoring** project: `.migration/project.json` keeps `"type": "da"`. The new files have no effect on authors or on how pages render today. They make the blocks ready for a later move to Universal Editor.

## Current state (verified)
- There are no component models anywhere yet: no `component-models.json`, `component-definition.json`, `component-filters.json`, `models/` folder, or `blocks/*/_*.json`.
- `package.json` has only lint scripts. There is no `build:json` and no JSON-merge tooling.
- The blocks' `metadata.json` files are migration variant descriptors. They are not models and stay as they are.
- No block JS checks variant classes. Blocks tell cells apart by content (picture-only cell = image), so models only need to produce the right cell order.
- **tabs-showcase (confirmed in code):**
  - Cell 1 is the tab label.
  - All other cells are merged into one panel.
  - The panel is split into the app card and the product card at the first H4, or at the picture-only element directly before that H4.
  - So the model order must be: label → app text → app image → product image → product text (starting with H4).

## Approach
Follow the standard xwalk boilerplate layout:
- **Per-block models:** each block gets `blocks/<block>/_<block>.json` with `definitions`, `models` and `filters`.
- **Shared models:** `models/` holds the page, section and default-content models, plus three aggregator files that pull in every block's file with `"...": "../blocks/*/_*.json#/…"`.
- **Merged root files:** `component-models.json`, `component-definition.json` and `component-filters.json` are generated by an `npm run build:json` script using `merge-json-cli` and `npm-run-all` (devDependencies only, no runtime build step).
- **Field conventions:** `image` + `imageAlt`, `link` + `linkText`/`linkTitle`, and `text` (richtext), with field collapsing so that each item still renders as the cells the decorate functions expect.

## Block model design

| Block | Kind | Item model → cells | Notes |
|---|---|---|---|
| cards | container | `card`: `image`, `text` (richtext) → [image \| body] | Filter allows `card` only |
| cards-news | container | `card-news`: `image`, `imageAlt`, `text` → [image \| body] | Eyebrow, H3 link, date and author all go in richtext |
| cards-overlap | container | `card-overlap`: `image`, `imageAlt`, `text` → [image \| body] | CTAs are link-only paragraphs in the richtext |
| cards-spotlight | container | `card-spotlight`: `image` (optional), `imageAlt`, `text` → [image \| body] | An empty image cell gives a "list item" card, which the JS supports |
| carousel-hero | container | `slide`: `image`, `imageAlt`, `text` → [image \| content] | Label, eyebrow, heading, description and CTA all go in richtext |
| tabs-showcase | container | `tab`: `title` (text), `appText` (richtext), `appImage` + `appImageAlt`, `productImage` + `productImageAlt`, `productText` (richtext, H4 first) | Order matches the panel split in `tabs-showcase.js` |
| columns | columns | template `columns: 2, rows: 1` | Filter: `text`, `image`, `button`, `title` |
| columns-banner | columns | template `columns: 2, rows: 1` | Image-first or text-first order is set by the author |
| columns-link-lists | columns | template `rows: 1`, columns = number of `.listed-col` in the imported homepage | Filter: `text`, `button`, `title` |
| hero | simple | `hero`: `image`, `imageAlt`, `text` | `hero.js` is empty, so the model only follows the boilerplate |
| widget | simple | `widget`: `link` (widget path) | Single cell |
| fragment | simple | `fragment`: `reference` (aem-content) | Boilerplate standard |

Not modeled as blocks:
- `header` and `footer` are auto-loaded fragments.
- `section-metadata` is replaced by the `section` model's `style` field. Its select options come from section styles already used in `page-templates.json`: `light-beige`, `orange`, `centered`.

## Known risk to flag (no fix needed now)
- In Universal Editor output, an image field may render as a bare `<picture>` inside its cell rather than wrapped in a `<p>`.
- `isPictureOnly()` in `tabs-showcase.js` uses `el.querySelector('picture')`, which only finds a picture *inside* the element, so it would miss a bare `<picture>`.
- On DA this doesn't matter. I'll note it in the report as a small JS fix to make if the site ever moves to Universal Editor. I won't change block JS as part of this work.
